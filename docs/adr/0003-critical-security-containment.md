# ADR 0003: Critical Security Containment (SEC-01, SEC-03, SEC-04, SEC-13, SEC-14, SEC-18, SAFE-01)

- **Status:** Accepted
- **Date:** 2026-10-24
- **Authors:** Senior Health-Informatics Architect / Antigravity Engineering Team
- **Applies to:** `MedicalPortal.Core`, `MedicalPortal.Infrastructure`, `MedicalPortal.Web`, `docker-compose.yml`

---

## 1. Context & Business Drivers

The independent security audit ([`docs/security-audit-2026-10-24.md`](../security-audit-2026-10-24.md)) identified several critical vulnerabilities and clinical safety risks that undermined the authentication, authorization, and transport security of the Springfield Health prototype:

1. **SEC-01 (Critical - Auth Bypass & Privilege Escalation):**
   - `SessionService.ValidateSessionAsync` lazily auto-created a valid database session for *any* unrecognized `sid` present in a structurally valid JWT, completely bypassing session revocation and allowing zombie or forged sessions to persist indefinitely.
   - `AuthFilters.cs` blindly copied the `role` claim from the incoming JWT token directly into `HttpContext.Items["Actor"]` without verifying against the authoritative `UserAccount` record in the database. A token issued with an elevated role (or a user whose role was later downgraded by an administrator) retained elevated privileges until the token expired.
   - `docker-compose.yml` embedded hardcoded cluster JWT secret keys (`ThisIsAClusterSecretKeyForMultiInstanceDeployments12345!`).

2. **SEC-03 (Critical - Plaintext Production Transport):**
   - The edge proxy and application lacked HTTPS enforcement, secure cookie directives when behind TLS terminators, and HSTS headers.

3. **SEC-04 (Critical - Silent Fake Payments in Production):**
   - If `Stripe:SecretKey` was empty or set to placeholder text in Production, the application silently fell back to `FakePaymentGateway`, which accepted arbitrary payments and simulated credit cards without moving real funds.
   - `docker-compose.yml` set `STRIPE_USE_FAKE=true` even in production profiles.

4. **SEC-13 (High - Known Fallback HMS Secrets & Plain HTTP):**
   - `HmsWebhookHandler` defaulted to `demo-hms-webhook-secret` when unconfigured.
   - `HmsClient` defaulted credentials to `admin`/`Admin` and permitted unencrypted HTTP endpoints.

5. **SEC-14 (Medium - SignalR Bypasses Session Revocation):**
   - `PortalHub.OnConnectedAsync` validated JWT signatures and claims in-memory but bypassed `ISessionService.ValidateSessionAsync`. Revoked sessions or deactivated accounts retained full real-time push and notification access.

6. **SEC-18 (Medium - Plain HTTP Outbound Geolocation Call):**
   - `PublicIpService` sent plaintext HTTP GET requests to `http://ip-api.com` transmitting client IP metadata across public internet paths.

7. **SAFE-01 (Safety - Unconditional Demo Decision-Support Data):**
   - `Program.cs` registered `DemoInteractionKnowledgeBase` and `DemoAllergyKnowledgeBase` across all environments including Production, with no fail-fast guard prohibiting unverified demo clinical decision support from being used on real patients.

## 2. Decision & Implementation

### 2.1 Elimination of Lazy Session Creation & Token-DB Reconciliation (SEC-01)
- **Deleted Lazy Session Creation:** In `SessionService.cs`, the fallback block that created new `UserSession` records on cache/DB miss was removed. If a session is not found in the database, `ValidateSessionAsync` immediately returns `false` with `RevocationReason = "session_not_found"`.
- **Authoritative Database Reconciliation:** In `AuthFilters.cs`, after validating the session via `ISessionService`, the filter retrieves the active `UserAccount` from EF Core:
  - Verifies `account.IsActive == true`. If deactivated, returns HTTP 401 and revokes the session.
  - Verifies `account.Role.ToString() == claims.Role`. If mismatched, returns HTTP 401 and revokes the session.
  - Replaces `claims.Role` and `claims.UserAccountId` with authoritative database values in the downstream `Actor` claims.
- **Authorization Versioning (`AuthorizationVersion`):**
  - Added `AuthorizationVersion` integer property (default: 1) to `UserAccount` entity via migration `AddAuthorizationVersion`.
  - Added `authVersion` claim to JWT access tokens generated by `TokenService`.
  - `SessionService.ValidateSessionAsync` asserts that `account.AuthorizationVersion == claims.AuthorizationVersion`.
  - When an administrator modifies a user's role or status in `AdminController`, `AuthorizationVersion` is incremented and `RevokeAllSessionsForUserAsync` is invoked, immediately revoking all active sessions across both HTTP and SignalR.

### 2.2 SignalR Session Validation Unification (SEC-14)
- Updated `PortalHub.cs` to resolve `ISessionService` and call `ValidateSessionAsync` during `OnConnectedAsync`.
- Sessions that are revoked, expired, belong to deactivated users, or have outdated `AuthorizationVersion` or mismatched roles are rejected before the connection is established.

### 2.3 Production Fail-Fast Validation (SEC-03, SEC-04, SEC-13, SAFE-01)
Added two-tier fail-fast assertions in `Program.cs` when `Environment.IsProduction()`:
1. **Pre-Build Configuration Checks:**
   - **Payments:** Throws `InvalidOperationException` if `Stripe:UseFake` is true, or if `Stripe:SecretKey` is missing, empty, or contains known placeholders (`sk_test_placeholder`, `demo`, `test`).
   - **HMS Integration:** Throws `InvalidOperationException` if `Hms:UseFake` is true, or if `Hms:WebhookSecret` is missing or contains placeholder values (`demo-hms-webhook-secret`), or if `Hms:BaseUrl` is not a secure HTTPS URL.
   - **Clinical Decision Support:** Throws `InvalidOperationException` if `Clinical:UseDemoKnowledgeBase` is true or if licensed clinical knowledge bases are not configured.
   - **Secrets:** Throws `InvalidOperationException` if `Jwt:Key` contains default demo/cluster strings (`ThisIsAClusterSecretKeyForMultiInstanceDeployments12345!`).
2. **Post-Build Service Descriptor Validation:**
   - Resolves `IPaymentGateway`, `IHmsClient`, `IInteractionKnowledgeBase`, and `IAllergyKnowledgeBase` from `app.Services` and confirms none are test/fake implementations (`FakePaymentGateway`, `FakeHmsClient`, `DemoInteractionKnowledgeBase`, `DemoAllergyKnowledgeBase`).
3. **Transport Hardening:**
   - Configured `app.UseHsts()` with 365-day max age, include subdomains, and preload directives.
   - Added `Strict-Transport-Security: max-age=31536000; includeSubDomains; preload` and `X-Content-Type-Options: nosniff` headers.

### 2.4 Removal of Known Fallback Secrets & Plain HTTP Geolocation (SEC-13, SEC-18)
- Removed default demo webhook secrets from `HmsWebhookHandler.cs` and hardcoded credentials (`admin`/`Admin`) from `HmsClient.cs`.
- Completely removed cleartext `http://ip-api.com` network calls in `PublicIpService.cs`, eliminating external metadata leakage.
- Removed static cluster JWT secret keys and `STRIPE_USE_FAKE=true` from `docker-compose.yml`.

## 3. Verification & Negative Abuse Tests

A comprehensive test suite [`backend/tests/MedicalPortal.Tests/CriticalSecurityContainmentTests.cs`](../../backend/tests/MedicalPortal.Tests/CriticalSecurityContainmentTests.cs) was introduced:
1. `AuthFilter_ForgedToken_UnknownSessionId_RejectedWith401`: Verifies that a cryptographically signed JWT with an unrecognized `sid` is rejected with 401 Unauthorized (lazy creation eliminated).
2. `AuthFilter_RoleTamperingInToken_RejectedWith401`: Verifies that a valid user token tampered with an elevated role claim (`ADMIN`) is rejected with 401 Unauthorized.
3. `AuthFilter_DeactivatedUser_ActiveToken_RejectedWith401`: Verifies that deactivating a user immediately causes active tokens to be rejected.
4. `AuthFilter_RoleChange_IncrementsAuthVersion_RevokesSessionImmediately`: Verifies that changing a user's role increments `AuthorizationVersion` and rejects previously issued tokens.
5. `SignalR_PortalHub_RejectsConnection_WhenSessionIsUnknown`: Verifies that SignalR hubs reject connections with unpersisted session IDs.
6. `SignalR_PortalHub_RejectsConnection_WhenSessionIsRevoked`: Verifies that SignalR hubs reject revoked sessions.
7. `SignalR_PortalHub_RejectsConnection_WhenRoleClaimMismatchesDatabase`: Verifies that SignalR hubs reject tokens with role tampering.
8. `ProductionStartup_Throws_WhenStripeUseFakeIsTrue`: Verifies production fail-fast on fake payments.
9. `ProductionStartup_Throws_WhenStripeSecretKeyIsMissing`: Verifies production fail-fast on missing payment credentials.
10. `ProductionStartup_Throws_WhenHmsWebhookSecretIsDemoDefault`: Verifies production fail-fast on fallback HMS secrets.
11. `ProductionStartup_Throws_WhenHmsBaseUrlIsHttpNotHttps`: Verifies production fail-fast on plain-HTTP HMS endpoints.
12. `ProductionStartup_Throws_WhenClinicalDemoKnowledgeBaseIsEnabled`: Verifies production fail-fast on demo clinical data.
13. `ProductionStartup_Throws_WhenJwtKeyIsDemoClusterSecret`: Verifies production fail-fast on hardcoded JWT secrets.
14. `PublicIpService_DoesNotMakePlainHttpCallsToIpApiCom`: Verifies that `PublicIpService` makes no outbound plaintext HTTP calls.

**Test Results:** All 275 tests passed (259 baseline + 16 new negative/containment tests).
